# Blind Pulser Response-Fibre Scope

## Scientific Question

Does the preregistered response-fibre ranking, frozen before Pulser finite-error
outcomes are opened, remain predictive when evaluated through an independent
local Pulser 1.9 numerical execution path?

## Frozen Prediction Protocol

The prediction protocol is the frozen twenty-path response-fibre ranking
recorded by the G4 prospective layer. The committed blind summary records:

```text
source_protocol_sha256 = 2bf2d193f9839a7f204984705d3ccef9ddead2bf3cf906e56b52138b402dd71c
prediction_freeze_sha256 = 535f3ed5821997059f5568bab76e824aad12183414199ded755a40a2fa08dad1
source_outcomes_unlocked = false
```

## Prediction And Outcome Chronology

The response-fibre prediction was frozen before the Pulser finite-error
outcomes were revealed. The blind Pulser program then evaluates the frozen
twenty-path schedule set and computes the statistical gates against the
predeclared ranking.

## 20 Paths x 6 Error Points

The blind test evaluates 20 phase schedules at the six declared finite-error
points, for 120 local Pulser propagations:

```text
paths = 20
error_points_per_path = 6
propagations = 120
```

## Pulser Version And Locked Requirements

The workflow installs [`requirements-pulser-blind.txt`](../requirements-pulser-blind.txt).
The committed summary records:

```text
pulser = 1.9.0
pulser_simulation = 1.9.0
```

## Statistical Gates

The preregistered gates are:

- all 120 propagations are finite;
- Spearman rho is at least 0.80;
- one-sided permutation p-value is below 0.05;
- best-vs-worst bootstrap 95% confidence interval has positive lower bound;
- the result beats the phase-total-variation baseline.

## Independent Components

The blind layer is independent in the following senses:

- Pulser propagation implementation;
- numerical simulation route used by Pulser/Qutip;
- prospective outcome reveal after prediction freeze;
- statistical evaluation of the frozen ranking against Pulser outcomes.

## Shared Model Assumptions

The blind layer shares:

- the documented two-atom model boundary;
- pulse schedules generated by the repository protocol;
- the declared six finite-error points;
- the response-fibre prediction protocol.

## Non-Claims

This validation does not test:

- PASQAL Cloud;
- FRESNEL;
- physical QPU execution;
- calibration drift;
- SPAM;
- decoherence;
- atom loss;
- many-body scaling.

It is not an Arb/Krawczyk proof and it does not modify the formal exact-root
certificate.
